# Dungeon balance audit / next-session handoff (PR #264)

Status: **inventory and a provisional stone-drop curve only**. Economic calibration, strict economy CI and new difficulty targets are **next session's work**, not claims of this change. Keep this PR unmerged and undeployed until explicit permission.

## Terminology and nonnegotiable scenario rules

- "F" in the existing balance suites denotes a dungeon **layer**, with **five enemy encounters per layer**. Distinguish layer from individual encounter index stored in `dungeon-floors.csv`.
- 1–10F: **no healing magic** in the player policy (the existing `test-dungeon-progression-simulation.mjs` already suppresses healing to layer 10). No HP/MP recovery **items** or resurrection **items** anywhere in the balance scenarios. Do not turn these into hidden aids.
- Status-cleansing items allowed **only from 51F**. General/all-status cleansing (`luna_stone` / `clear_all`) allowed **only from 71F**. Maintain an honest supply and carry-slot ledger; no invented items or refill between floors.
- Original game goals for narrow wins, comfortable wins and nearly exhausted MP **are hard, mandatory CI acceptance criteria**. Do **not** weaken/relabel them, increase powers solely to hide failures, or treat Wilson confidence-interval overlap as a pass. Preserve the exact approved band goals and margins. Any additional goals need explicit approval, not invented target thresholds.
- Preserve existing EXP/legacy-save conversion, the signed pre-conversion rescue copy, rollback protections, Google Drive sync and new alchemy/magic ink features. Test with GitHub Actions, not locally; do not merge, release or deploy.

## B. Hard balance objectives already encoded in the repository

Source: `tests/test-dungeon-default-balance.mjs`. These are **already approved baseline requirements and must never be softened**:

- For 1–20F ten-layer sorties, observed win rate **99–100%**; 1–10F winning run median MP remaining **50–100%**, with **no healing magic**.
- For 21–100F ten-layer sorties, observed win rate **90–97%** AND stricter interior margin **92–95%**; winning run median MP remaining **0–15%**.
- Wilson intervals are *diagnostics only*; observed point estimate must pass. Number of seeded trials/coverage must be explicit. One or more failed bands => strict CI red.
- Report by decade and every floor: entry/exit HP%, MP%, reached/cleared denominators, boss/normal fight, status cleanses consumed, cumulative resources and failures. Preserve intra-sortie persistence and the distinction between full-HP/MP sortie start and consecutive encounters.
- Additional `test-dungeon-progression-simulation.mjs` checks early Lv3/5/19 full clears and high MP reserves and Lv150 late-game low MP reserve; maintain them as explicit additional goals; do not silently drop them.
- The current `dungeon-balance-strict` job already fails on main and on PR; this is **not** an excuse to turn it off. Report which bands and parameters miss targets.

## C. What the current CI does NOT actually establish

1. `scripts/simulate-dungeon-stones.mjs` assumes **100% victory and all rank awards**, grants the next eligible rank unconditionally, and only simulates the rank-gated 1–100F campaign plus 101F/91–100F farming; no real combat losses, retry cost, actual inventory or ink expenses. Despite the authored master having 500 fights (100 layers), stone curve extrapolates through 150F; such extra-depth runs need an explicit model.
2. `test-dungeon-default-balance.mjs` starts each decade with a predetermined strong reference spell set and invests a percentage of stones already earned in an optimistic, guaranteed-clear projection. It does not run a single realistic account whose **actual** rolls, spending, replacement circles and combat defeats consistently carry across 100F.
3. No conservation ledger reconciles **gross earned - lost-on-death - spent = held** for stones, ink, collections, alchemy ingredients and consumables across repeated sorties. No measured probability of being resource-starved after replacing 1, 2 or 5 circles.
4. Coverage of practical user behavior is narrow: new circles splitting investment, additional ink usage, short/long farm routes, low-power starter circles, alchemy yield and chance of having sufficient specific/all-status cleansers are not combined.
5. Approved victory and low-MP targets are assessed in an isolated fight simulator without end-to-end economy feedback. A resource-accurate model should report **both** combat-goal attainment and number of farming fights/returns needed to attain it; merely multiplying stones until win rate rises would be a misleading pass.
